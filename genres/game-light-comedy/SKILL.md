# 游戏轻喜剧写作

## 触发条件

项目或用户任务是游戏、轻小说、沙雕、搞笑，或明确要求按游戏轻喜剧方法写、改、审章节。

## 执行步骤

1. 先读项目设定、技能数值表、搞笑大纲和上一章。以已写正文和作者设定为权威。缺设定时先问，不要随意打破游戏底层数值逻辑。
2. 判断当前任务：开书设计、前三章、邪道破局、喜剧战后结算，还是审阅。
3. 开书：确认轻喜剧卖点、淘汰危机、游戏规则与物理引擎、队伍互动、前三章承诺、本卷两道门槛。展开读 `01-structure.md`。
4. 开篇：第1章马上失败的游戏目标，第2章规则错位与策略试错，第3章翻盘开新局并交付新任务。展开读 `02-opening.md`。
5. 章内：按本章功能只选一种主写法：「规则预期与反差笑点 / 失败仍推进目标 / 队伍互损与结算 / 轻喜剧开篇任务 / 机制升级而非梗堆叠 / 笑点后的任务钩子」。展开读 `03-methods.md` 对应节，按「上场先定 → 步骤 → 纸上必须看见」执行。
6. 成文：句长约 20–30 字，段长约 25–40 字，对白大约一成到两成。笑点前立预期，笑点后给结算。展开读 `04-prose.md`。
7. 写完用 `05-checklist.md` 核对。勾不上的项回到对应写法改。若环境能改文件，先给作者看修改再写入。

只拷本文件也能工作。同目录 `01`–`05` 是展开，不是前提；写具体场时优先打开对应节。

## 成功标准

- 游戏目标清晰可测且机制严密自洽
- 笑点来自一本正经的目标与荒诞执行的反差
- 队伍吐槽与互损推进分工并产生实战结果
- 笑点之后必然结算清晰的进度、战利品与新任务

## 硬约束

- 读者承诺：用可测游戏目标和职业规则提供进度反馈，让认真目标与荒诞执行形成轻喜剧错位，但笑点后仍有结果
- 不要靠无脑堆砌过气网络烂梗水字数
- 不要写毫无游戏机制支撑的纯无厘头乱闹
- 区间不是合格线；只有笑话而无游戏进度推进比数字偏离更严重
