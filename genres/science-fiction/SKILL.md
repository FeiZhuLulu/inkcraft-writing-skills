# 科幻写作

## 触发条件

项目或用户任务是科幻、赛博、星际、太空，或明确要求按科幻方法写、改、审章节。

## 执行步骤

1. 先读项目设定、技术参数表、物理大纲和上一章。以已写正文和作者设定为权威。缺设定时先问，不要随意违背基础物理常识。
2. 判断当前任务：开书设计、前三章、技术破局、文明抉择，还是审阅。
3. 开书：确认科幻卖点、初始设备故障、技术边界与资源窗口、文明秩序、前三章承诺、本卷两道门槛。展开读 `01-structure.md`。
4. 开篇：第1章设备或通信故障，第2章修复测试与任务约束扩大，第3章文明尺度问题与下一项可执行任务。展开读 `02-opening.md`。
5. 章内：按本章功能只选一种主写法：「技术故障转任务 / 任务约束与资源 / 文明尺度逐层揭示 / 技术异常开篇 / 界面/设备动作化 / 任务结算与更大问题」。展开读 `03-methods.md` 对应节，按「上场先定 → 步骤 → 纸上必须看见 → 本场计数」执行。
6. 成文：句长约 20–35 字，段长约 30–40 字，对白大约两成上下。术语绑定设备、界面与反馈，先写后果再补解释。展开读 `04-prose.md`。
7. 写完用 `05-checklist.md` 核对。勾不上的项回到对应写法改。若环境能改文件，先给作者看修改再写入。

只拷本文件也能工作。同目录 `01`–`05` 是展开，不是前提；写具体场时优先打开对应节。

## 成功标准

- 技术问题与物理法则形成坚硬的行动制约
- 任务受能源、工质、航程与时间窗口严格限制
- 宏观文明命题通过个体可操作的工程决策落地
- 章末留下可验证的下一项技术或远航任务

## 硬约束

- 读者承诺：让技术能力、任务约束与资源窗口相互制衡，并把文明尺度命题落到个体可执行决策
- 不要开篇大段科普宇宙社会学论文或银河编年史
- 不要让飞船与武器脱离能量守恒与物理定律神棍化
- 区间不是合格线；专业术语讲座打断舱内抢修比数字偏离更严重

本场计数按所选写法执行，数字只来自该写法的量化控制：

- 技术故障转任务：可观察的设备或通信故障至少 1；故障结果必须接到任务约束上。
- 任务约束与资源：时间、能源或航程限制至少 2；是否使用的选择至少 1。
- 文明尺度逐层揭示：尺度放大步骤至少 2；一次性文明史倾倒最多 1。
- 技术异常开篇：技术事实最晚第 3 章交付；生存或文明问题至少 1。
- 界面/设备动作化：界面或身体反馈至少 1；影响行动的参数至少 1。
- 任务结算与更大问题：局部技术目标至少 1；更大文明风险至少 1。
