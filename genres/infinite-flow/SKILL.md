# 无限流写作

## 触发条件

项目或用户任务是无限流、诸天流、副本、轮回，或明确要求按无限流方法写、改、审章节。

## 执行步骤

1. 先读项目设定、副本规则表、积分大纲和上一章。以已写正文和作者设定为权威。缺设定时先问，不要随意更改副本底层机制。
2. 判断当前任务：开书设计、前三章、副本推演、通关结算，还是审阅。
3. 开书：确认无限流卖点、初始绝境处境、副本规则与即死条件、队伍机制、前三章承诺、本卷两道门槛。展开读 `01-structure.md`。
4. 开篇：第1章规则不全的副本危机，第2章队伍分工与倒计时施压，第3章规则反转结算并留下下一局新任务。展开读 `02-opening.md`。
5. 章内：按本章功能只选一种主写法：「副本规则落地 / 副本队伍分工 / 倒计时资源选择 / 规则未全知的开篇 / 副本结算回写主线 / 通关后的更高风险」。展开读 `03-methods.md` 对应节，按「上场先定 → 步骤 → 纸上必须看见」执行。
6. 成文：句长约 20–35 字，段长约 25–35 字，对白大约一成到两成。规则写成可执行限制，先写选择再补规则。展开读 `04-prose.md`。
7. 写完用 `05-checklist.md` 核对。勾不上的项回到对应写法改。若环境能改文件，先给作者看修改再写入。

只拷本文件也能工作。同目录 `01`–`05` 是展开，不是前提；写具体场时优先打开对应节。

## 成功标准

- 副本规则具备严密的逻辑与可测试性
- 队伍分歧由真实的信息差与自私生存诉求驱动
- 倒计时与可消耗资源形成真实紧迫感
- 副本收益与伤势真实回写主线状态

## 硬约束

- 读者承诺：用副本规则、队伍分工、倒计时和资源结算制造局部闭环，并让每局收益改变下一局风险
- 不要把无限流写成开箱兑换清单与数据刷屏
- 不要让主角在未知规则下无脑莽撞平推
- 区间不是合格线；解释打断生死逃杀比数字偏离更严重
